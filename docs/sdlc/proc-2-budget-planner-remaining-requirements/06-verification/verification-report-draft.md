## Known gaps

- **REQ-23 (2 of 3 scenarios)**: "Derived statistics carry the same ownership" and "Statistics for one user are isolated from another user's data" have no automated test. The implementation does scope statistics by user (`app/api/statistics/route.ts` calls `receiptStore.allForUser(CURRENT_USER_ID)` before computing the breakdown), but there is no `app/api/statistics/route.test.ts` at all, and `lib/statistics/statisticsService.test.ts` tests the pure aggregation function against a plain receipts array with no per-user filtering exercised. This is implemented-but-unverified, not unimplemented.
- **REQ-24 (both scenarios, partial)**: No test computes an actual budget total after a delete via `calculateMonthlyBudget`. The two closest tests (`receiptStore.test.ts` "removes a receipt so it no longer appears in all()" and "zeroes out a month's total when the last receipt is deleted") only assert on `store.all()` length/emptiness, not on a computed total. The "150 PLN → 100 PLN after deleting a 50 PLN receipt" scenario specifically has no test at any level.
- **REQ-29 and REQ-30 (all 6 combined scenarios)**: The two new screens (`app/receipts/page.tsx`, `app/budget/page.tsx`) have zero automated test coverage — no component/page test file exists for either. Both were manually verified end-to-end in a browser during implementation (receipt upload → list → category correction → budget summary), which also caught two real bugs (a `globalThis` singleton issue and a Next.js `searchParams`-await issue), but that verification is not repeatable by the automated suite.
- **REQ-28 "try again" message text**: The OCR/LLM failure tests verify the error is not swallowed and is not silently retried, but no automated test asserts the literal user-facing message text ("try again") — that is confirmed only by the same manual browser pass referenced above.
- **Environment quirk, not a code defect**: The Meridian indexer's default 256 MiB buffer pool is insufficient on this machine once `node_modules` exists; re-indexing requires `MERIDIAN_LBUG_BUFFER_POOL_SIZE=2147483648` (or larger). This is a local tooling constraint, unrelated to the application code under test.
- **No static-analysis / lint coverage**: This project has no linter, formatter-in-check-mode, or type-checker script configured at all (confirmed by inspecting `package.json` and the repo root for ESLint/Prettier config files). `tsc` is a devDependency but is not wired to any script. Nothing in this change adds or removes that gap — it predates this stage — but it means no automated static check ran over the 26 requirements' new code beyond what `next build`'s own TypeScript compilation would catch, and that build was only run manually during implementation, not as part of this stage's gate.
